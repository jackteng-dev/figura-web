## 構圖、轉檔與實際大小

第一輪主圖構圖過滿，安全留白不足，已退回。第二輪生成較寬鬆的 1254×1254 原圖，六張商品圖經人工確認後統一裁切 `[x=147,y=120,w=960,h=960]`，完整保留角色與底座，**未放大**。因此本輪詳情圖實際為 960²；規範的 1024² 是後續原生解析度目標，不能把這批素材稱為原生 1536²。

Banner 原圖 1672×941，安全裁切 `[4,2,1664,936]` 後縮為 1536×864（16:9）；尚未製作手機專用構圖，不宣稱已通過首頁響應式整合。

## 驗證範圍

- `npm run build` 通過（Vue 型別檢查＋Vite production build，Vite 6.51s）。仍有既有 legacy script、動靜態 import 與大 chunk 提示，未列為已解決。
- 本機 Chrome headless 八項檢查通過：[機讀結果](verification/figure-images-2026-11-19.json)。全 AI、混合、截斷目錄分別顯示準確 AI 提示；無 AI 及空目錄不宣稱其為 AI 商品；390px 提示沒有橫向溢出。
- 獨立樣本頁 1440px／390px：七張圖片皆可解碼、選用 AVIF、標示可讀、沒有橫向溢出。檢查時主動載入所有圖片以驗證，不代表一般首屏會載入所有角度。
- FFprobe 驗證 49 個衍生檔尺寸；保存 hash／bytes，禁止放大或錯誤長寬比。
- 首頁行為驗證使用瀏覽器內攔截的公開 API 回應，未寫入 DB、未使用員工帳號、未測正式環境、未做 LCP／手機實機效能測量。
- 後端未修改，未跑 Maven；WebP／AVIF／多圖尚未接入後端目前的單主圖 API。

## 保存與重做

新素材位於 `src/brand/figure-render-samples/`，原始 PNG、兩張舊概念參考圖、local session 與瀏覽器截圖留在忽略的 `work/figure-render-samples/`。不修改 `src/assets/` 或 `package-lock.json`。

`python scripts/prepare-figure-samples.py` 使用 FFmpeg／FFprobe，從該工作站的 local `session.json` 及原圖重新轉檔並生成樣本頁。腳本不會產圖、不呼叫 API、不改商品資料。原圖與 session 未入 Git，因此另一台機器需先取回本機 archive 或重建 session，不能宣稱新 clone 可無條件重做相同 AI 結果；生成本身也沒有 seed 可保證重現。

真正 GLB 僅在規範中完成評估。本輪沒有 `.glb`、建模工程或 viewer。建議後續只選一款、取得完整可用模型後才做按需載入試點；先不把資源投入大規模 3D 檢視器。
